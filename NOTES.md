## What this is

An end-to-end pipeline for reading Saudi bank checks. A check image goes in, and the system extracts and cross-checks the two monetary amounts written on it:

- **Legal amount** — handwritten Arabic text, e.g. عشرة آلاف ريال فقط لا غير
- **Courtesy amount** — handwritten digits, e.g. 10000

Four stages feed into each other in sequence: detect both regions, read each one with its own recognizer, convert the Arabic words to an integer, compare.

## Dataset quirks you need to know

**Bounding box format.** YOLO normalized (`class cx cy w h`). Class **0 = legal**, class **1 = courtesy**. Every file has exactly two rows. **The order within the file is not consistent** — always identify by class id, never by position.

**One missing annotation.** `ac00048` has an image but no bounding-box file. It is skipped everywhere, hardcoded as `MISSING = {'ac00048'}`. That leaves 1,799 usable training images, not 1,800.

**Courtesy labels are messier than they look.** Each line is `Cac#####.tif \t [list]` holding digits 0–9 as integers, plus special tokens that are not consistent across splits:

- `10` — start/end boundary marker, stripped before training
- `'.'` in train — decimal separator (riyals.halalas)
- `11` in test — the same separator, encoded differently
- `'/'` in train — also a fraction separator

`utils._normalise_ca_token` maps `11` and `'/'` onto `<SEP>` but leaves `'.'` as its own token, so the 13-token vocabulary carries **two distinct symbols for the same concept**. This costs real accuracy: in the courtesy recognition notebook the model sometimes emits `.` where the reference holds `<SEP>`, and a semantically correct read is scored as an error. Collapsing the two before scoring would be the fix.

**Legal labels are sub-word fragments, not words.** Each line is `Lac#####.tif ['subword', 'tokens', ...]` where words are split into pieces — ريال arrives as `['ر', 'يا', 'ل']`. The files also contain invisible RTL/LTR Unicode control characters that must be stripped before parsing; `utils.parse_legal_amounts` handles this. If you `print()` raw lines from `LegalAmounts.txt` they may render backwards in a terminal. That is normal.

**Legal vocabulary is built over train and test together** — 288 tokens, so there are zero out-of-vocabulary tokens at inference. This was deliberate: the label files were available and the vocabulary is coverage, not supervision. It is also worth being honest that it flatters the result, because the recognizer is never tested against a token it has not seen.

**Images.** Grayscale TIFF, LZW compressed, roughly 1152 × 422. Courtesy crops average ~230 × 50 px, legal crops ~660 × 97 px.

**Index gap.** Test images start at `ac03000`, not `ac01800`. Do not assume contiguous indices.

## Architecture decisions

### Detection — YOLOv8s

`yolov8s.pt` pretrained on COCO, fine-tuned on the 1,799 labelled images. The annotations were already in YOLO format, so no conversion was needed.

- 80/20 train/val split, seed 42
- `imgsz=640`, `epochs=100`, `patience=20`, `batch=16`
- Images are symlinked rather than copied, avoiding a duplicate of roughly 2 GB of TIFFs
- Best weights land at `artifacts/yolo_runs/yolov8s_checks/weights/best.pt`
- Evaluation uses our own IoU metrics rather than YOLO's built-in mAP, so the numbers are directly comparable to the published work on this dataset

### Recognition — CRNN + CTC

The same architecture for both amounts, differing only in vocabulary size and input dimensions:

```
CNN (7 blocks, BatchNorm + ReLU):
  (1→64)    MaxPool(2,2)  → H/2,  W/2
  (64→128)  MaxPool(2,2)  → H/4,  W/4
  (128→256, 256→256) MaxPool(2,1) → H/8,  W/4
  (256→512, 512→512) MaxPool(2,1) → H/16, W/4
  (512→512) MaxPool(2,1)  → H/32, W/4   (one row when H=32)

BiLSTM: 2 layers, 256 hidden per direction, dropout 0.2
Linear: 512 → vocab_size
LogSoftmax → CTC loss (blank = index 0)
```

After the CNN the height collapses to 1 and width becomes the time axis, T = W/4. CTC requires T ≥ label length, which sets minimum widths:

- Courtesy: `MIN_W=64` → T ≥ 16, longest label 10 ✓
- Legal: `MIN_W=160` → T ≥ 40, longest label 29 ✓

**Decoding** is greedy — argmax per timestep, collapse repeats, drop blanks. No beam search; the sequences are short enough that it makes no difference.

**Crops.** Training crops come from ground-truth boxes, so the recognizers learn on a clean signal. Test crops come from the detector's own predictions, so evaluation reflects the real pipeline. Where the detector misses a box entirely, the ground-truth box is used as a fallback so that recognition is not scored on a detection failure.

**Why not TrOCR?** The labels are custom sub-word tokens rather than standard Unicode characters, so TrOCR's pretrained decoder does not align with this label space without substantial rework. CRNN with CTC over a custom vocabulary is the cleaner fit.

That assumption was later tested rather than assumed — see `06-rt-detr-trocr-exploration.ipynb`, where TrOCR reaches 78.82% digit accuracy against this CRNN's 95.17%. Note the caveat recorded there: that run reports `train_loss: nan` throughout and was never diagnosed, so it is evidence about that particular run rather than a clean verdict on the architecture.

### Verification — rule-based

`utils.legal_text_to_digits()` turns a predicted Arabic token sequence into an integer:

1. Join sub-word tokens back into a string
2. Strip noise words (ريال, فقط, لا غير, and similar)
3. Greedy-match against `_AMOUNT_MAP`, ordered large-to-small so thousands are consumed before hundreds before units
4. Try two-word phrases (أحد عشر = 11) before single words

The result is compared against the courtesy prediction. Agreement means verified.

It is best-effort and will not handle every Arabic phrasing, particularly amounts with halalas. Cross-correction between the two recognizers is what recovers some of that.

## The tokenization result

The single largest improvement in the project came from changing the label representation, not the model.

Sub-word tokenization gives a 288-class vocabulary over a few thousand training samples, so most classes are seen a handful of times. Rebuilding at the character level — 24 Arabic letters plus a space — collapses that to roughly 25 classes and gives every class far more examples. Character error rate fell **50.5% → 9.02%**, a 5.6× reduction, with no change to the architecture.

## The post-processing that failed

A minimum-edit-distance layer was built to repair broken CTC output against a dictionary of amount words. It made things much worse: **CER 9.02% → 80.49%**. The raw CTC output is what the project reports.

The reason is worth keeping in mind for any similar correction step. CTC errors are frequently *segmentation* errors rather than spelling errors — a word arrives split or merged rather than misspelled. Nearest-dictionary-word matching has no way to detect this, so it confidently replaces a fragment with a complete but wrong word, converting a partially correct output into an entirely wrong one. A correction layer needs a confidence threshold and the ability to decline.

## Metrics

| Stage | Metric |
|---|---|
| Detection | Accuracy @ IoU ≥ 0.50 / 0.75 / 0.90, mean IoU |
| Courtesy | Digit accuracy `(1 − (I+D+S)/N) × 100`, share with 0 / 1 / ≥2 errors |
| Legal | CER and WER |
| Verification | Share of checks where the converted legal amount matches the courtesy amount |

All implemented in `utils.py`: `detection_metrics`, `courtesy_summary`, `legal_summary`.

## Running on a new machine

```bash
pip install -r codebase/requirements.txt
# copy the four dataset folders into the repository root
cd codebase && jupyter notebook
```

Run the notebooks in numeric order; each writes artifacts the next one reads.

**GPU.** Training was done on an NVIDIA RTX 5060. Device is auto-detected per notebook: CUDA, then MPS, then CPU. On Apple Silicon it works but is slow and will thermal-throttle on long runs.

## Miscellaneous

- The YOLO dataset uses symlinks rather than copies. On Windows, `populate_split` in the detection notebook needs `shutil.copy2` instead.
- The recognizers save test predictions keyed by filename (`Cac#####.tif`, `Lac#####.tif`). Verification matches them on the shared stem `ac#####`.
- Training in the legal recognition notebook was interrupted and resumed from the best checkpoint; the stored output records this.
